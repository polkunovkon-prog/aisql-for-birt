# AI BIRT — «ИИ-конструктор отчётов» для Eclipse BIRT 4.7

Плагин для дизайнера отчётов Eclipse BIRT 4.7: ИИ-помощник, который должен
собирать отчёты (`.rptdesign`) по текстовому описанию — так, как это сделал бы
пользователь руками. Плагин встраивается штатными механизмами Eclipse
(OSGi-бандлы + публичные точки расширения): BIRT и Eclipse **не патчатся**,
версия BIRT остаётся 4.7.0 — все существующие отчёты продолжают открываться.

Текущая версия — **1.0.0 (enterprise)**: агентная сборка отчёта
**инструментами по элементам** (ADR-0003) + стек защиты и управляемости
(ADR-0004). Модель собирает отчёт пошагово: `report_new` → `add_datasource`
→ `add_dataset` → `add_table`/`add_chart`/… → `report_validate` →
`report_done`; каждый вызов — транзакция Design API с валидацией и откатом.
Агент правит **любые** существующие `.rptdesign` (`report_open` +
`report_inspect`). Протокол — штатный OpenAI tool calling с запасным
текстовым протоколом `TOOL …` для локальных серверов.

Защита: enterprise-политика (fail-closed), режимы защиты от промпт-инъекций
(off/flag/strict + заборы вокруг недоверенного контента), маскирование ПДн
(email/телефоны/карты/ИНН/СНИЛС) в уходящем тексте, журнал аудита с цепочкой
хэшей SHA-256 и выгрузкой в syslog/SIEM. Классический спец-режим v0
(«Создать отчёт…» → JSON-спецификация → сборка) сохранён полностью;
выразительные средства — как в 0.7 (таблицы до 5 уровней группировки,
итоги, подсветка, фильтры, сетки, изображения, списки, диаграммы,
колонтитулы, любая СУБД через JDBC).

Совместимость: **BIRT 4.7 (Eclipse Oxygen, Java 8) и BIRT 4.25 (2026,
Java 21)** — один набор офлайн-тестов (**691 проверка**) проходит на обеих
линиях; байт-код Java 8. Агентная приёмка с рендером (classicmodels/Derby):
17/17. CI: матрица 4.7+JDK8 / 4.25+JDK21.

## Что уже умеет (M1–M3, версия 0.7.0)

- панель **«ИИ-конструктор отчётов»** (чат с моделью): открывается через
  `Window → Show View → ИИ для BIRT`, в перспективе BIRT «Отчёт» добавляется
  рядом с Outline; отправка — `Ctrl+Enter`; интерфейс на русском;
- связь с **OpenAI-совместимым сервером** локальной модели (`/v1/chat/completions`,
  `/v1/models`); настройки по умолчанию — сервер и модель, согласованные для этой машины;
- **создание отчёта**: «Создать отчёт…» (ТЗ → спецификация) и
  «Собрать .rptdesign…» (спецификация → файл отчёта, диалог пути и пароля БД),
  результат открывается в редакторе BIRT; спецификация проверяется строго,
  ошибки объясняются по-русски, SQL — только на чтение;
- **правка собранного отчёта** («Правка отчёта…»): замечание → новая
  спецификация → список изменений до применения, резервная копия и
  «Отменить правку»; кэш «отчёт → спецификация» сохраняет возможность правки
  после перезапуска Eclipse;
- **предпросмотр из панели** («Просмотр…»): PDF движком BIRT открывается
  системным просмотрщиком — без вкладки Preview и настройки Web Browser;
- **схема БД для ТЗ** («Схема БД…»): в поле ввода вставляются только имена
  таблиц и колонок (метаданные; строки данных не читаются);
- **выразительные средства**: стили надписей и ячеек, вычисляемые колонки,
  итоги (`sum`/`count`/`avg` и др.), до 5 уровней группировки таблицы и
  списка, сортировка по нескольким ключам, подсветка и фильтр строк,
  сетки, изображения (PNG-файл или base64), колонтитулы страниц (`{page}`, `{pages}`,
  `{title}`, `{date}`), диаграммы — столбчатые, линейные, круговые
  (`category`/`value`/`series`/`aggregate`);
- **любая СУБД**: данные читает движок BIRT через JDBC-драйвер, установленный
  в Eclipse; для чтения схемы (только метаданные) используется
  `JDBCDriverManager` с запасным путём `Class.forName` + `DriverManager`
  (PostgreSQL — быстрый путь);
- **комплектный драйвер PostgreSQL** (42.7.3) с регистрацией штатной точкой
  расширения `driverinfo` — PostgreSQL 17 (SCRAM) подключается без замены
  файлов BIRT; BIRT и Eclipse не патчатся;
- **агентный режим**: «Конструктор (агент)…» — ТЗ → пошаговая сборка
  инструментами с прогрессом в чате; «Правка (агент)…» — выбор любого
  `.rptdesign` → агент изучает структуру и правит по замечанию;
- **защита**: политика предприятия (fail-closed), защита от инъекций,
  маскирование ПДн, аудит с цепочкой хэшей и syslog (SIEM);
- **страница настроек** (`Window → Preferences → «ИИ-конструктор отчётов (BIRT)»`):
  адрес сервера, модель, ключ доступа, температура, таймаут, ограничение ответа,
  системная инструкция, включение аудита; кнопка **«Проверить соединение»**;
- **журнал аудита** `~/.ai-birt/ai-birt-audit.jsonl` (JSONL; ключи и пароли не попадают);
- запросы и сборка выполняются в фоне (Job) — интерфейс Eclipse не блокируется;
- понятные ошибки с подсказками: нет связи, неверный ключ (HTTP 401),
  неизвестная модель (HTTP 404), таймаут, не-JSON-ответ, ошибки спецификации.

## Быстрый старт

```bash
./releng/build.sh          # сборка бандлов (javac 8 против jar-ов Eclipse)
./releng/test.sh           # офлайн-тесты (691 проверка, без реального сервера)
./releng/agent-selftest.sh # приёмка агента: инструменты → отчёт → PDF/HTML (Derby)
./releng/fetch-birt.sh ЦЕЛЬ 4.25  # (опц.) jar-ы BIRT без установленного Eclipse
./releng/install.sh        # установка в Eclipse + контрольный headless-запуск
```

Затем:

1. запустите Eclipse: `/home/pka/eclipse/eclipse`;
2. откройте панель: `Window → Show View → ИИ для BIRT → «ИИ-конструктор отчётов»`;
3. при необходимости поправьте подключение: `Window → Preferences → «ИИ-конструктор отчётов (BIRT)»`.

Удаление: `./releng/uninstall.sh`.

## Настройки

Файл `~/.ai-birt/ai-birt.properties` (права `600`, можно править вручную —
изменения подхватываются без перезапуска Eclipse):

| ключ | смысл | по умолчанию |
|---|---|---|
| `llm.baseUrl` | адрес OpenAI-совместимого сервера (`…/v1`) | `http://192.168.100.152:8888/v1` |
| `llm.model` | идентификатор модели | `ornith-ai/Ornith-1.5-35B-A3B-GGUF` |
| `llm.token` | ключ доступа; пусто — запросы без `Authorization` | — |
| `llm.temperature` | температура генерации (0…2) | `0.3` |
| `llm.timeoutSec` | таймаут одного запроса, секунд | `900` |
| `llm.maxTokens` | ограничение длины ответа (`0` — не передавать) | `0` |
| `chat.systemPrompt` | системная инструкция чата | русская инструкция |
| `audit.enabled` | журнал аудита в `ai-birt-audit.jsonl` | `true` |
| `db.driver` | JDBC-драйвер для чтения схемы БД | `org.postgresql.Driver` |
| `db.url` | адрес базы для чтения схемы БД | `jdbc:postgresql://127.0.0.1:5432/hogwarts` |
| `db.user` | пользователь базы | — |
| `db.password` | пароль базы для чтения схемы (только если отмечено «Сохранить пароль») | — |

Каталог настроек можно переопределить системным свойством `aibirt.config.dir`
(используется тестами).

## Журнал аудита

`~/.ai-birt/ai-birt-audit.jsonl` — по одной JSON-записи на строку:
`ts` (ISO-8601), `user`, `app` (версия), `function`, `decision`, `outcome`,
`ms`, `model`, `error`, `detail`. Секреты в журнал не пишутся.
Журнал можно выключить (`audit.enabled=false`).

## Принципы

- **Никаких патчей**: только бандлы в отдельном каталоге (`<Eclipse>/aisql`) и
  регистрация в `bundles.info`; чужие строки и файлы не изменяются.
- **Установка без root**: Eclipse стоит в домашнем каталоге; установка и
  удаление — обычным пользователем, с копированием прежнего `bundles.info`.
- **Модель — смысл, клиент — формат**: отчёты собираются штатным Design API
  BIRT по компактной спецификации (ADR-0001) или инструментам агента
  (ADR-0003), а не генерацией XML моделью — это снижает риск «сломанного
  файла» и даёт понятные ошибки проверки. Каждый вызов инструмента —
  транзакция с откатом; сохранение атомарное, с резервной копией.
- **Пошаговость вместо «всё или ничего»**: ошибки ловятся на шаге, где
  возникли, и возвращаются модели для самокоррекции (паттерн MCP isError).
- **Данные не уходят в модель**: ИИ видит только текст ТЗ и вопросов из
  панели; по кнопке «Схема БД…» в поле ввода вставляются только метаданные
  (имена таблиц и колонок), и лишь пользователь решает, оставить ли их в ТЗ;
  строки из базы читает локально движок BIRT при рендере; пароль БД в модель
  не передаётся, SQL — только на чтение (`docs/SECURITY.md`).
- **Проверяемость**: офлайн-тесты, контрольный headless-запуск со стартовым
  маркером в журнале, журнал аудита.
