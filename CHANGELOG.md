# Журнал изменений

## 1.0.0 — 07.11.2026 (enterprise: агентные инструменты, защита, аудит)

Версия поднимает проект до enterprise-уровня: агентная сборка отчёта
**инструментами по элементам** (ADR-0003), стек защиты и управляемости
(ADR-0004), кросс-версионная совместимость BIRT 4.7…4.25 и CI.

### Агентная сборка инструментами (ADR-0003)

- **17 инструментов** (`tools/ReportTools.java`): `report_new`, `report_open`,
  `report_inspect`, `report_validate`, `report_done`, `add_datasource`,
  `add_parameter`, `add_dataset`, `set_page`, `add_label`, `add_table`,
  `add_grid`, `add_image`, `add_chart`, `add_list`, `remove_element`,
  `db_schema`. Модель собирает отчёт пошагово, а не одним большим JSON.
- **DesignSession** (`report/DesignSession.java`): каждая мутация — транзакция
  командного стека Design API (`startTrans/commit/rollback`), откат при
  ошибке с сообщением, пригодным для самокоррекции модели; `rollbackAll()`
  (undo до дна стека); атомарное сохранение (временный файл → `ATOMIC_MOVE`,
  резервная копия `.bak`).
- **Правка ЛЮБЫХ отчётов**: `report_open` + `report_inspect` (структура:
  источники, наборы с SQL и колонками, параметры, элементы тела) — агент
  правит существующие `.rptdesign`, созданные человеком, а не только свои.
- **Манифест сессии**: «теневая» спецификация (источники/наборы/параметры)
  наполняется при открытии чужого отчёта; по нему проверяются перекрёстные
  ссылки новых фрагментов (`ReportSpec.parse*Fragment` — строгий разбор
  одного элемента с теми же проверками, что и у полной спецификации).
- **Tool calling** (`LlmClient.chatWithTools`): штатный протокол OpenAI
  (`tools`, `tool_calls`, `role:"tool"`) + запасной текстовый протокол
  `TOOL имя {json}` для локальных серверов без tools (`agent.nativeTools`).
- **AgentSession** (`agent/`): цикл с лимитом итераций (24 по умолчанию,
  сужается политикой), счётчиками вызовов/ошибок, прогрессом для UI,
  аудитом каждого вызова; при лимите — сохранение best-effort.
- **UI**: кнопки «Конструктор (агент)…» и «Правка (агент)…» в панели;
  ход работы печатается в чат («→ add_table: ок»); спец-режим v0
  («Создать отчёт…» → спецификация) сохранён полностью.
- **BirtErrorHints**: типовые семантические ошибки BIRT получают подсказку
  «что делать» — в `report_validate` и чат.

### Защита (ADR-0004)

- **Enterprise-политика** (`security/BirtEnterprisePolicy.java`): файл
  `ai-birt-enterprise.properties` (или `-Daibirt.enterprise.policy=…`);
  отключение инструментов (`tools.disabled`), запрет правки чужих отчётов,
  лимит итераций, режим инъекций, закрепление маскирования и аудита;
  **fail-closed** — сломанный/отсутствующий файл = самые строгие правила.
- **Защита от промпт-инъекций** (`security/PromptInjectionDefense.java`):
  режимы off/flag/strict; HIJACK-правила (блокируют в strict) отделены от
  MARKER-меток; забор (fence) вокруг ТЗ и результатов интроспекции;
  Unicode-границы для кириллицы (работают одинаково на JDK 8 и 21).
- **Маскирование ПДн** (`security/PiiDetector.java`): email, телефоны
  (РФ/E.164), карты (Лун), ИНН-10/12, СНИЛС — в уходящем тексте.
- **Аудит с доказуемостью**: журнал `ai-birt-audit.jsonl` получил `seq`,
  `host`, `session` и **цепочку хэшей SHA-256** (`prev`/`hash`);
  `verifyChain()` проверяет целостность (кнопка в настройках).
- **Syslog → SIEM** (`security/AuditSyslog.java`): RFC 5424-подобные
  сообщения по UDP, severity warning для отказов; тест-кнопка в настройках.
- **Страница настроек**: разделы «Агентная сборка» и «Защита» (режим
  инъекций, маскирование, syslog, целостность журнала, статус политики);
  закреплённые политикой поля заблокированы.

### Совместимость и сборка

- **BIRT 4.7 (Eclipse Oxygen, Java 8) и BIRT 4.25 (2026, Java 21)**
  проверяются одним набором тестов; байт-код остаётся Java 8.

## 0.7.0 — 22.10.2026 (диаграммы, list, условия, колонтитулы, любая СУБД)

- **Диаграммы** (`type: "chart"`): столбчатая, линейная и круговая. Поля
  `category`, `value`, `series` (необязательно), `aggregate`
  (`sum`/`count`/`avg`/`min`/`max`), `title`, `width_mm`/`height_mm`.
  Модель строится штатным Chart API BIRT и передаётся элементу через
  `ChartReportItemImpl.setModel`; XML сохраняется в `xmlRepresentation`.
  Размер блока диаграммы задаётся в точках (иначе движок рисует в 0×0 и
  диаграмма молча исчезает), шрифт — DejaVu Sans (кириллица в PDF/SVG).
  Привязки `boundDataColumns` получают `dataType` из колонок набора.
- **Список** (`type: "list"`): шапка, группировка, сортировка, итоги;
  подвал группы собирается через grid (BIRT не допускает Row в Footer
  ListGroup).
- **Условия**: подсветка строк таблицы (`highlight`) и фильтр таблицы
  (`filter`) безопасными JS-выражениями (`HighlightRule`/`FilterCondition`,
  оператор `is-true`).
- **Колонтитулы страницы** (`report.page.header`, `report.page.footer`): строки
  с токенами `{page}`, `{pages}`, `{title}`, `{date}`; `{date}` —
  `<value-of>new Date()</value-of>`.
- **Любая СУБД**: чтение схемы через `JDBCDriverManager` с запасным путём
  `Class.forName` + `DriverManager` (PostgreSQL — быстрый путь); настройки
  `db.driver`/`db.url`/`db.user`/`db.password`.
- **Приёмка**: headless-приложение получило режим рендера готового
  `.rptdesign` (без спецификации); диаграммы проверены в Eclipse OSGi —
  PDF/HTML, SEVERE=0. Прежние 4 спецификации M2 повторно приняты.
- **Полный цикл с локальной моделью** (22.10.2026): эталонное ТЗ
  `docs/TZ-PROMPT-hogwarts.md` → спецификация → `.rptdesign` → PDF на
  4 страницы и HTML, SEVERE=0; фильтр `H-GRA` — 43 строки, 2 страницы.
  Первый ответ модели (два `?`, один `params`) отклонён понятным сообщением,
  промт уточнён — повторный ответ принят.
- **Проверки**: 471 офлайн-проверка.

## 0.4.0 — 19.10.2026 (итоги, покрытие корпуса BIRT)

Расширение словаря спецификации по результатам разбора 655 отчётов
пользователя (`own.rar`) и приёмки 16 форм EHR.

- **Итоги таблицы** (`total` у колонки, `total_label` у таблицы): строка
  «Итого» в подвале таблицы — `sum`/`count`/`avg`/`min`/`max`; реализовано
  через вычисляемую колонку с `aggregateFunction` и аргументом-ссылкой на
  привязку колонки, как в дизайнере BIRT. Покрывает типовые статистические
  отчёты «список + Итого».
- **Исправлена привязка вычисляемых колонок**: выражение теперь хранится
  в отдельной вычисляемой колонке таблицы, а элемент данных ссылается на её
  имя. Запись выражения прямо в `resultSetColumn` приводила к тому, что при
  сохранении модель BIRT перенаправляла ячейку на другую колонку с тем же
  выражением (агрегат «Итого» перехватывал колонку данных — в каждой строке
  показывался итог; поймано на приёмке, добавлен тест).
- **Приёмка и совместимость**: 654/655 отчётов `own.rar` открываются моделью
  BIRT 4.7 (655-й — файл нулевого размера в архиве); 16/16 форм
  `ehr_template_v2` открываются; рендер форм упирается только в недоступную
  внешнюю БД `192.0.2.40` (ограничение среды).
- **Проверки**: 275 офлайн-проверок; приёмка `m2-selftest` — групповой отчёт
  с итогами: 165 строк HTML (160 данных + 4 заголовка групп + «Итого»),
  «Балл» построчно, итог 6320, SEVERE=0.
- **Документация**: ADR-0002 (итоги и правило привязки вычисляемых колонок),
  ROADMAP — программа расширения покрытия элементов BIRT (колонтитулы, grid,
  изображения, диаграммы, кросс-таблицы и т. д. с метрикой по корпусу).

## 0.3.0 — 19.10.2026 (M2 полностью + старт M3)

Правка собранного отчёта, предпросмотр из панели, расширения спецификации
и контекст схемы БД (только метаданные).

- **Правка отчёта по замечанию** («Правка отчёта…»): модель получает текущую
  спецификацию и замечание текстом, возвращает полную новую спецификацию;
  панель показывает список изменений (`SpecDiff`) до применения, сборка идёт
  во временный файл с атомарной заменой и резервной копией
  `имя.rptdesign.bak-yyyyMMdd-HHmmss`, есть кнопка **«Отменить правку»**;
  правка запрещена, если файл менялся вручную. Решения — `docs/ADR-0002-edit-and-extensions.md`.
- **Кэш «отчёт → спецификация»** (`BuiltReports`, `~/.ai-birt/reports-built.json`):
  правка/предпросмотр работают и после перезапуска Eclipse; запись привязана
  к файлу по времени изменения и размеру.
- **Предпросмотр из панели** («Просмотр…»): headless-рендер PDF движком BIRT
  (с диалогом параметров) и открытие системным просмотрщиком — без зависимости
  от вкладки Preview (отключена в BIRT 4.7) и настройки Web Browser Eclipse.
- **Расширения спецификации v0** (обратно совместимые): стили надписей
  (курсив, цвет) и ячеек (жирный, курсив, цвет, фон, фон шапки), вычисляемые
  колонки (`row["…"] * 10` через привязки `boundDataColumns`), группировка
  таблицы: `group_by` + `group_title` + `group_count` (счётчик строк в подвале
  группы). Промт модели обновлён, старые спецификации валидны.
- **Схема БД для модели — только метаданные** (старт M3): «Схема БД…» читает
  `DatabaseMetaData` (имена таблиц/колонок, лимиты 60×40) и вставляет текст
  в поле ввода — пользователь видит его в ТЗ и сам решает, что уйдёт модели;
  строки данных не читаются. Настройки `db.driver/db.url/db.user/db.password`
  в `~/.ai-birt/ai-birt.properties` (пароль — по галочке «Сохранить»),
  headless-инструмент `DbSchemaTool` для приёмки. Аудит: `db/schema`.
- **Исправления**: параметры отчёта в предпросмотре приводятся к типу
  (числа — `Integer`/`Double`, `validateParameters` движка); проверка журнала
  движка в приёмке считает только `ReportEngine_*.log`; пакет
  `com.aisql.birt.core.jdbc` экспортирован для OSGi (кнопка «Схема БД…»
  в Eclipse); замечания о BIRT: не-ASCII пароль в скрытом свойстве читается
  с потерей символов — панель в этом случае спрашивает пароль заново.
- **Проверки**: новые наборы `SpecDiffTest`, `BuiltReportsTest`, `DbSchemaTest`;
  расширены `ReportBuilderTest` (стили, группировка, вычисляемые колонки,
  чтение пароля) и `ReportSpecTest` — всего 263 проверки, 0 ошибок.
  Приёмка `m2-selftest.sh` прогоняет две спецификации (базовая + с
  группировкой и стилями) и проверку текста схемы БД; оба рендера проходят
  с настоящими данными hogwarts и кириллицей в PDF.
- **Документация**: ADR-0002 (правка, расширения, предпросмотр, схема),
  обновлены README, USAGE, TESTING, SECURITY, ROADMAP.
