# ТЗ-промт: отчёт по студентам Хогвартса (приёмка M2)

Готовый текст задания для проверки полного цикла «чат → спецификация →
`.rptdesign`» на тестовой базе **hogwarts** (та же, что у плагина для DBeaver).

**Как пользоваться**

1. Откройте панель «ИИ-конструктор отчётов»
   (`Window → Show View → ИИ для BIRT`).
2. Скопируйте **весь текст между линиями** ниже (без служебных заголовков
   строки-разделителя) в поле ввода.
3. Нажмите **«Создать отчёт…»** — модель вернёт спецификацию; в ленте
   появится её сводка (имя файла, параметры, источник, набор данных).
4. Нажмите **«Собрать .rptdesign…»**, выберите файл (по умолчанию —
   первый проект рабочей области) и введите **пароль** пользователя
   `agent_user` (в самом ТЗ пароля нет — это правило формата).
5. Eclipse откроет собранный отчёт в редакторе BIRT. Проверьте данные:
   **`Run → View Report → View Report (HTML)`** (вкладка `Preview` в BIRT 4.7
   отключена авторами — отчёт откроется в браузере) — в диалоге параметров
   оставьте `%` (все факультеты).

> Пароль базы данных вводится только в диалоге и сохраняется внутри
> `.rptdesign` в скрытом виде (как при сохранении пароля самим дизайнером) —
> чтобы предпросмотр и запуск работали сразу.

--------------------------------------------------------------------------

Сделай отчёт BIRT «Студенты Хогвартса по факультетам».

Подключение к базе данных (PostgreSQL):
- драйвер JDBC: org.postgresql.Driver
- строка подключения: jdbc:postgresql://127.0.0.1:5432/hogwarts
- пользователь: agent_user
- пароль в спецификацию не включай — его введут отдельно при сборке.

Схема базы (нужные таблицы):
- students(id, person_id, house_id, enrollment_year, grade_level, is_active),
  grade_level — целое от 1 до 7 (курс);
- people(id, first_name, middle_name, last_name, birth_date, gender, email, phone, is_active);
- houses(id, code, name, colors), коды: H-GRA — Гриффиндор, H-HUF — Люфен,
  H-RAV — Равенкл, H-SLY — Слизерин.

Содержимое отчёта:
1. Заголовок «Студенты Хогвартса по факультетам» — по центру, размер 14,
   жирный. Ниже мелкая (9) надпись по центру: «Отчёт сформирован плагином
   «ИИ-конструктор отчётов»».
2. Параметр отчёта house_code (строка) с подписью «Код факультета («%» — все)»
   и значением по умолчанию «%». Если задан код факультета (например, H-GRA) —
   в отчёт попадают только его студенты, «%» — все студенты.
3. Таблица со столбцами: «Фамилия» (people.last_name), «Имя» (people.first_name),
   «Факультет» (houses.name), «Курс» (students.grade_level, по центру).
   Порядок строк: по курсу, затем по фамилии.
4. Страница A4, книжная; поля: сверху/справа/снизу 10 мм, слева 15 мм.

Как выполнить запрос (используй именно такой SQL, один оператор SELECT,
два знака «?» для параметра house_code):
select p.last_name, p.first_name, h.name as house_name, s.grade_level
from students s
join people p on p.id = s.person_id
join houses h on h.id = s.house_id
where (? = '%' or h.code = ?)
order by s.grade_level, p.last_name

--------------------------------------------------------------------------

**Что должно получиться (ожидаемые результаты приёмки)**

| Проверка | Ожидание |
|---|---|
| Сборка | создан файл `<имя>.rptdesign`, отчёт открывается редактором BIRT |
| Предпросмотр, `%` | 160 строк данных (41 Гриффиндор, 39 Люфен, 40 Равенкл, 40 Слизерин) |
| Предпросмотр, `H-GRA` | только Гриффиндор, 41 строка |
| Экспорт в PDF (A4) | 4 страницы с таблицей (поле «Курс» — числа 1…7) |
| Язык | шапки и заголовки по-русски, кракозябр нет |
| Аудит | записи `function=report`, `action=spec` и `action=build`, `outcome=OK` в `~/.ai-birt/ai-birt-audit.jsonl` |

Если модель вернула не-JSON или спецификация не прошла проверку — в ленте
появится причина по-русски (например, «колонка … не описана в datasets…»);
поправьте ТЗ (обычно помогает явно назвать таблицы/колонки) и повторите
«Создать отчёт…».
