# Кросс-БД отчёт «Два мира в цифрах» — ТЗ и эталонные SQL

Комплект для приёмки двух плагинов на двух локальных базах PostgreSQL:

| База | Тема | Роль в отчёте |
|---|---|---|
| `hogwarts` | Хогвартс: студенты, факультеты, экзамены, клубы, библиотека | академический блок |
| `cadia` | Warhammer 40K: личный состав, командная структура, техника, приказы, снабжение | военный блок |

Отчёт **не выполняет SQL-join между базами**. Это два независимых JDBC-источника
в одном `.rptdesign`: каждый набор данных выполняется на своей базе, а объединение
происходит на уровне документа (разделы, KPI, графики, параметры). Домены не имеют
общего ключа, поэтому честного join «в лоб» нет. Если понадобится одна таблица,
склеенная из двух баз, это отдельная задача: `postgres_fdw`, `dblink` или ETL в
третью базу.

## Состав

```
docs/examples/crossdb/
├── README.md                 этот файл
├── TZ-DBEAVER.md             готовый промпт для DBeaver AI (2 подключения)
├── TZ-BIRT.md                готовый промпт для плагина BIRT
└── sql/                      проверенные эталонные SQL (fallback и приёмка)
    ├── hw-kpi.sql
    ├── hw-houses.sql
    ├── hw-results.sql
    ├── cd-kpi.sql
    ├── cd-ranks.sql
    ├── cd-units.sql
    ├── cd-equipment.sql
    ├── cd-orders.sql
    └── cd-supply.sql
```

## Порядок работы

1. Открыть DBeaver, подключиться к `hogwarts`, открыть AI Chat и вставить промпт
   из `TZ-DBEAVER.md` (раздел «Hogwarts»). Получить блоки `HW-1`…`HW-3`.
2. Переключиться на подключение `cadia`, вставить второй промпт. Получить блоки
   `CD-1`…`CD-6`.
3. Сверить полученные SQL с контрактами колонок. Если AI-модель DBeaver ошиблась,
   использовать файлы из `sql/` — они проверены на текущих данных.
4. Вставить SQL в `TZ-BIRT.md` вместо плейсхолдеров `<<<...>>>`, вставить промпт
   в плагин BIRT и собрать отчёт.
5. Собрать `.rptdesign`, проверить PDF/HTML и число диаграмм.

## Ожидаемый отчёт

A4 landscape, ориентировочно 8–11 страниц, верхний/нижний колонтитулы, два
параметра:

* `house_code` — код факультета (`H-GRA`, `H-SLY`, `H-HUF`, `H-RAV`, `%` — все);
* `regiment_code` — код полка (`CAD-8`, `%` — все).

### Раздел I. Хогвартс

1. KPI-таблица: студенты, активные, сотрудники, дисциплины, экзамены, средний
   балл, доля «Отлично», выдачи книг, участники клубов.
2. Таблица факультетов: студенты, активные, средний балл, «Отлично», завершившие
   обучение, клубы, библиотека, место. Подсветка факультетов ниже среднего балла
   по всем факультетам.
3. Столбчатая диаграмма: средний балл по факультетам.
4. Линейная диаграмма: средний балл по курсам (1–7), серии — факультеты.
5. Круговая диаграмма: распределение оценок.

### Раздел II. Кадиа

1. KPI-таблица: военные, активные, офицеры, потери, техника, исправная техника,
   запрошено, поставлено, доля поставок.
2. Таблица категорий званий: всего, активные, погибшие, раненые, выслуга, доля.
   Подсветка категорий с потерями.
3. Таблица командной структуры: армия → корпус → дивизия → бригада → полк →
   батальон, с численностью подчинённых. Нулевые подразделения скрыты фильтром.
4. Таблица техники, сгруппированная по типу: состояние, количество, доля внутри
   типа. Итог по количеству.
5. Столбчатая диаграмма: техника по типам и состоянию, серии — статусы.
6. Линейная диаграмма: приказы по годам, серии — типы приказов.
7. Таблица снабжения: позиция, запрошено, поставлено, отклонено, процент
   поставки. Подсветка позиций с поставкой ниже 25 %.

## Ограничение текущей версии 0.7.0

Диалог сборки BIRT-плагина запрашивает **один пароль на все источники данных**.
Поэтому оба JDBC-источника в этом ТЗ используют одного пользователя
`agent_user` (он имеет доступ к обеим базам). Это локальная приёмка, не
production-схема.

Варианты для production:

* создать отдельную роль `birt_reader` с `SELECT` в обеих базах и одним паролем —
  работает без доработки плагина;
* доработать плагин до диалога «пароль для каждого источника» — тогда можно
  оставить `agent_user` для `hogwarts` и `cadia_reader` для `cadia`.

Пароли не входят ни в спецификацию, ни в промпты, ни в SQL. Они вводятся только
в диалоге сборки.

## Проверено

Мульти-источниковый отчёт с двумя JDBC-подключениями и одним пользователем
собран и отрендерен в PDF/HTML без `SEVERE` (проверка на минимальной
спецификации). Эталонные SQL из `sql/` выполнены на текущих базах; количество
строк совпадает с таблицей выше.
