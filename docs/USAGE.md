# Использование

Плагин даёт четыре вещи:

1. **чат с локальной моделью** — вопросы про BIRT и проектирование отчётов (M1);
2. **создание отчёта из текстового описания** — модель возвращает
   спецификацию, плагин собирает `.rptdesign` штатным Design API BIRT
   (M2; выразительные средства — 0.7.0);
3. **правка собранного отчёта по замечанию** — «добавь колонку», «отсортируй»:
   модель возвращает новую спецификацию, панель показывает изменения и
   применяет их с резервной копией (0.3.0);
4. **предпросмотр и контекст схемы БД** — PDF из панели одним нажатием и
   чтение имён таблиц/колонок для ТЗ (только метаданные, 0.3.0).

## Панель «ИИ-конструктор отчётов»

Открыть:

- `Window → Show View → ИИ для BIRT → «ИИ-конструктор отчётов»`;
- в перспективе BIRT «Отчёт» (`Window → Perspective → Open Perspective → Отчёт`)
  панель добавляется в правую область рядом с Outline.

Кнопки панели:

| Кнопка | Что делает |
|---|---|
| **Отправить** (`Ctrl+Enter`) | вопрос модели в режиме чата; ответ печатается в ленте |
| **Создать отчёт…** | берёт текст из поля ввода как ТЗ и просит модель вернуть спецификацию отчёта; в ленте появляется сводка спецификации |
| **Правка отчёта…** | берёт текст из поля ввода как замечание к текущему отчёту; модель возвращает новую спецификацию, панель показывает список изменений и применяет их после подтверждения |
| **Собрать .rptdesign…** | собирает файл отчёта из готовой спецификации: спросит путь и пароль базы, откроет результат в редакторе BIRT |
| **Просмотр…** | выполняет отчёт движком BIRT (спросит параметры) и открывает PDF системным просмотрщиком |
| **Схема БД…** | читает у базы только имена таблиц и колонок и вставляет их текстом в поле ввода — как основу ТЗ |
| **Отменить правку** | возвращает отчёт к версии до последней применённой правки |
| **Очистить чат** | сбрасывает историю диалога |
| **Настройки…** | адрес сервера, модель, ключ доступа и т. п. |

### Как создать отчёт

1. Опишите отчёт в поле ввода: что показать, из каких таблиц, какие фильтры.
   Пример готового ТЗ (тестовая база hogwarts) — `docs/TZ-PROMPT-hogwarts.md`.
   Если имён таблиц/колонок не помните — нажмите **«Схема БД…»**: в поле ввода
   появится список таблиц и колонок (только метаданные), дополните его ТЗ.
2. **«Создать отчёт…»** — модель отвечает спецификацией. В ленте видно её
   сводку: имя файла, параметры, источник данных, набор, таблица. Если модель
   вернула не то — красное сообщение с причинами по-русски; поправьте ТЗ и
   повторите.
3. **«Собрать .rptdesign…»** — выберите файл (по умолчанию предлагается первый
   проект рабочей области) и введите пароль базы данных. Пароль не показывается
   в чате и не попадает в спецификацию: он сохраняется только внутри
   собранного отчёта (в скрытом виде), чтобы просмотр работал сразу.
4. **«Просмотр…»** — готовый PDF откроется системным просмотрщиком. Если у
   отчёта есть параметры, сначала появится диалог значений (например, код
   факультета; «%» — все значения). Это не зависит от вкладки `Preview`
   (в BIRT 4.7 она отключена авторами, Bugzilla 421879) и от настроек
   Web Browser Eclipse.
5. Собранный файл также открывается в редакторе BIRT: там доступны
   `Run → View Report` и `File → Export → Report` (PDF, XLSX и т. п.).

### Что можно описать в спецификации

| Тип (`type`) | Возможности |
|---|---|
| `label` | текст, размер, жирный/курсив, цвет, выравнивание |
| `table` | колонки, стили, вычисляемые колонки, итоги (`total`), до 5 уровней групп (`groups`), сортировка (`sort`), подсветка (`highlight`) и фильтр (`filter`) строк |
| `list` | шапка, группы, сортировка, итоги |
| `grid` | строки/ячейки, объединения, вложенные элементы, ширины колонок |
| `image` | PNG-файл (`path`) или данные `base64`, ширина/высота в мм |
| `chart` | столбчатая (`bar`), линейная (`line`), круговая (`pie`) |

Параметры отчёта, источники JDBC (любая СУБД), только запросы
`SELECT`/`WITH`. Колонтитулы страницы задаются в `report.page`:

```json
"report": { "name": "students", "title": "Студенты",
            "page": { "header": "Студенты — {title}",
                      "footer": "Стр. {page} из {pages}, {date}",
                      "show_header_on_first": true,
                      "show_footer_on_last": true } }
```

Пример диаграммы (все указанные колонки должны быть в `datasets[].columns`):

```json
{ "type": "chart", "kind": "bar", "dataset": "dsByHouse",
  "title": "Студентов на факультете", "category": "house_name",
  "value": "students", "aggregate": "sum",
  "width_mm": 160, "height_mm": 90 }
```

`kind` — `bar`, `line` или `pie`; `aggregate` — `sum` (по умолчанию),
`count`, `avg`, `min`, `max`; `series` (только для `bar`/`line`) добавляет
разбиение на ряды и легенду. Подробный формат — `docs/ADR-0001-report-spec-v0.md`
и `docs/ADR-0002-edit-and-extensions.md`.

### Как поправить отчёт

1. Соберите отчёт (или откройте отчёт, собранный конструктором) — панель
   помнит его спецификацию, в том числе после перезапуска Eclipse.
2. Напишите в поле ввода, что изменить: «добавь колонку с курсом»,
   «отсортируй по фамилии», «сделай шапку синей». Нажмите **«Правка отчёта…»**.
3. Модель вернёт новую спецификацию; панель покажет **список изменений**
   («было → стало») и спросит подтверждение. Ничего не применяется без
   согласия.
4. После применения рядом с отчётом остаётся резервная копия
   `имя.rptdesign.bak-yyyyMMdd-HHmmss`, а в ленте — путь к ней. Не подошло —
   **«Отменить правку»** вернёт прежнюю версию (пока Eclipse работает).
5. Если файл отчёта меняли вручную (в дизайнере) или он незнаком панели,
   правка не применяется: пересоберите отчёт из спецификации.

### Как посмотреть отчёт

**«Просмотр…»** — самый простой путь: панель выполняет отчёт и открывает PDF.
Файл сохраняется в `~/.ai-birt/preview/имя.pdf`; его можно отправить или
распечатать. Альтернатива — `Run → View Report` в редакторе BIRT (требует
настроенного Web Browser Eclipse; см. `docs/TESTING.md`).

### Схема базы данных

**«Схема БД…»** спрашивает драйвер, адрес, пользователя и пароль (по умолчанию —
значения из настроек), читает у базы **только метаданные** — имена таблиц,
представлений и колонок с типами — и вставляет текст в поле ввода. Строки
данных не читаются и в модель не передаются. Подходит любая СУБД, чей
JDBC-драйвер установлен в Eclipse (комплектный — PostgreSQL 42.7.3).
В текст попадают первые 60 таблиц по 40 колонок; служебные схемы СУБД скрыты.

Пароль можно сохранить в настройках плагина галочкой «Сохранить пароль
в настройках плагина» — тогда при следующем чтении схемы его не придётся
вводить. Без галочки он используется только для текущего подключения.

## Чат (вопросы про BIRT)

1. введите вопрос в нижнее поле;
2. отправьте — кнопкой **«Отправить»** или **`Ctrl+Enter`**
   (обычный Enter переносит строку);
3. ответ появится в ленте выше; пока модель отвечает, кнопки заблокированы,
   внизу виден статус.

Примеры вопросов для проверки:

- «Что такое параметр отчёта в BIRT и как его использовать?»
- «Чем отличается Grid от Table в BIRT?»
- «Как в BIRT связать таблицу с набором данных?»

## Настройки

`Window → Preferences → «ИИ-конструктор отчётов (BIRT)»` (или кнопка «Настройки…» в панели):

| Поле | Смысл |
|---|---|
| Адрес сервера (…/v1) | адрес OpenAI-совместимого сервера |
| Модель | идентификатор модели, например `ornith-ai/Ornith-1.5-35B-A3B-GGUF` |
| Ключ доступа | токен; хранится в файле настроек с правами 600 |
| Температура | «свобода» генерации: 0 — строго, 1 — смелее (для спецификаций используется пониженная 0,2) |
| Таймаут запроса | секунд на один ответ |
| Ограничение ответа | `0` — не ограничивать |
| Системная инструкция | роль/стиль ответов модели в чате |
| Журнал аудита | включение записи в `~/.ai-birt/ai-birt-audit.jsonl` |

**«Проверить соединение»** обращается к серверу и пишет результат рядом с
кнопкой: «Связь есть. Моделей на сервере: N; выбранная модель найдена» — либо
причину ошибки.

Подключение к базе для кнопки «Схема БД…» задаётся в её диалоге и хранится в
файле настроек (`db.driver`, `db.url`, `db.user`, `db.password` — пароль
только по галочке). Правка файла вручную тоже работает.

## Файлы на диске

- `~/.ai-birt/ai-birt.properties` — настройки (можно править вручную);
- `~/.ai-birt/ai-birt-audit.jsonl` — журнал аудита: `chat/answered`,
  `report/spec`, `report/build`, `report/edit-spec`, `report/edit`,
  `report/preview`, `db/schema`; ключ и пароли в журнал не попадают;
- `~/.ai-birt/reports-built.json` — кэш «отчёт → спецификация» для правки
  и предпросмотра после перезапуска (привязка по пути, времени изменения
  и размеру файла);
- `~/.ai-birt/preview/*.pdf` — последние предпросмотры;
- рядом с отчётом: `имя.rptdesign.bak-yyyyMMdd-HHmmss` — резервные копии
  перед правкой.

Изменения в файле настроек подхватываются без перезапуска Eclipse.

## Кириллица в PDF

Отчёты, собранные плагином, используют шрифт `DejaVu Sans` — он встраивается
в PDF, и русский текст читается. Предпросмотр из панели шрифты настраивает сам.
Для просмотра через `Run → View Report` шрифты должны быть видны движку BIRT:
на этой машине они подключены в JDK (`<java-home>/lib/fonts`, скрипт
`releng/install-viewer-fonts.sh`). Если PDF на другой машине окажется без
кириллицы — установите шрифты `fonts-dejavu-core`, выполните
`releng/install-viewer-fonts.sh` и перезапустите Eclipse; отчёты, собранные
до 18.10.2026, нужно пересобрать.

## Безопасность данных

Данные из базы в ИИ-модель **не передаются**: модель видит только текст ТЗ и
вопросов, которые вы пишете в панели, и возвращает спецификацию (описание
отчёта и SQL текстом). При работе со схемой модель получает только имена
таблиц и колонок — и только если вы сами оставили этот текст в ТЗ. Строки из
PostgreSQL читает движок BIRT локально при просмотре/экспорте отчёта. Пароль
базы вводится отдельным диалогом и в модель не отправляется; SQL — только
`SELECT`/`WITH`. Подробно — `docs/SECURITY.md`.

## Что происходит при ошибках

Ошибки показываются в ленте чата красным с понятным текстом:

- `Не удалось подключиться…` — сервер выключен или недоступен;
- `HTTP 401 …` — неверный ключ (проверьте `llm.token`);
- `HTTP 404 …` — проверьте адрес (`llm.baseUrl`) и модель;
- `Сервер не ответил за N с` — увеличьте таймаут или повторите;
- `Ответ сервера не является JSON…` — сервер отвечает не как OpenAI API;
- `спецификация не принята: …` — модель вернула не-JSON или спецификация не
  прошла проверку (причины перечислены списком);
- `Ошибка сборки: …` — не удалось сохранить отчёт (нет прав на каталог,
  пароль не принят базой и т. п.); подробность записывается в журнал аудита;
- `Ошибка применения правки: …` — файл отчёта не изменён, прежняя версия
  на месте;
- `Правка не применена: в редакторе есть несохранённые изменения…` —
  сохраните или закройте редактор и повторите;
- `Ошибка чтения схемы: …` — проверьте адрес/пользователя/пароль базы.
