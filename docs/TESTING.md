ручные (GUI, выполняет пользователь). Ниже — состояние на 18.10.2026.

## 1. Автоматические проверки (офлайн)

```bash

```

Что проверяется (без обращения к реальному ИИ-серверу и без базы данных):

| Набор | Что покрыто |
|---|---|

| `BirtSettingsTest` | файл настроек: значения по умолчанию, создание, запись/чтение, многострочная инструкция, незнакомые ключи, устойчивость к мусору, ASCII-экранирование значений, комментарии |
| `ChatHistoryTest` | история диалога: порядок ролей, системная инструкция, обрезка по объёму, очистка |
| `AuditLogTest` | журнал аудита: формат JSONL, поля записи, дописывание, выключение |
| `LlmClientTest` | клиент ИИ на заглушечном HTTP-сервере: успешный ответ, варианты `content`, ошибки 401/404/500, не-JSON ответ, пустой ответ, `finish_reason`, список моделей, недоступный сервер, адрес с завершающим слэшем |
| `ReportSpecTest` | спецификация отчёта v0: разбор, проверки (неизвестные поля, имена, SQL, `?`↔`params`, колонки, параметры страницы), сводка, оборот `toJson`/`parse`, ответ модели в ограждении ```` ``` ```` и в тексте |

### 3.3 Ручной чек-лист M2 (GUI, для пользователя)

1. **Запуск**: `/home/pka/eclipse/eclipse`; в `<workspace>/.metadata/.log`
   должна быть строка `AI BIRT UI plugin started, version 0.2.0`.
2. **Спецификация**: скопируйте ТЗ из `docs/TZ-PROMPT-hogwarts.md` в поле
   ввода панели чата и нажмите «Создать отчёт…». Ожидание — лента показывает
   «ИИ — спецификация отчёта:» со сводкой (имя файла, параметр `house_code`,
   источник `jdbc:postgresql://127.0.0.1:5432/hogwarts`, таблица 4 колонки).
   Если ответ модели не прошёл проверку — красная ошибка с причинами.
3. **Сборка**: «Собрать .rptdesign…» → выберите файл (например, в проекте
   рабочей области) → введите пароль `agent_user`. Ожидание: в ленте «Отчёт
   собран», отчёт открывается в редакторе BIRT.
4. **Данные**: в редакторе отчёта `Run → View Report → View Report (HTML)`
   (вкладка `Preview` в BIRT 4.7 отключена автором, Bugzilla 421879; отчёт
   откроется в браузере — см. «Известные особенности»). В диалоге параметров
   оставьте `%` — должно быть **160 строк** (41 Гриффиндор, 39 Люфен,
   40 Равенкл, 40 Слизерин). Затем повторите просмотр, указав `H-GRA`, —
   должна остаться **41 строка** (только Гриффиндор).
5. **Экспорт**: `Run → View Report → View Report (PDF)` либо
   `File → Export → Report → PDF` — A4, 4 страницы, кириллица читается.
6. **Аудит**: в `~/.ai-birt/ai-birt-audit.jsonl` появляются записи
   `function=report`, `action=spec` и `action=build`, `outcome=OK`.
7. **Отказы**: испортите ТЗ (например, «сделай отчёт, который удаляет
   студентов») — спецификация не должна собраться: в ленте появится причина
   про запрещённый SQL, файл не создаётся.

Результат GUI-проверки 18.10.2026 (пользователь): шаги 1–3 пройдены —
аудит `~/.ai-birt/ai-birt-audit.jsonl` содержит `spec` (10:42) и `build`

## 4. Известные особенности

- **просмотр отчёта** (`Run → View Report`) открывается во **внешнем браузере**
  через настройки Eclipse: `Window → Preferences → General → Web Browser`.
  В скопированной с другой машины рабочей области там могут остаться
  неработающие пути (например, `/snap/bin/firefox`, snap-пакетов в Debian
  нет) — их нужно заменить на имеющийся браузер: `/usr/bin/chromium`,
  параметры `%URL%`. Путь вида «…/firefox» лучше не использовать: Eclipse
  запускает его устаревшим механизмом `-remote openURL(...)`, который
  современный Firefox не понимает;
- ответ модели печатается целиком после готовности (потоковая печать — задел на будущее);
- закрытие/повторное открытие панели сбрасывает историю диалога;
- в перспективе «Отчёт» панель добавляется рядом с Outline; если перспектива
  была изменена вручную, место размещения может отличаться — вид всё равно
  доступен через Show View;
- ответы модели зависят от загруженной модели на сервере — при первом запросе
  модель может загружаться в память (первый ответ дольше);
- формат спецификации v0 намеренно узкий: надписи, таблицы, параметры, JDBC
  (см. `docs/ADR-0001-report-spec-v0.md`); диаграммы, grid, группировки —
  следующие этапы;
- в собранном отчёте пароль сохраняется в скрытом виде (base64), как это
  делает сам дизайнер BIRT при сохранении пароля: это нужно для предпросмотра
  и запуска без повторного ввода пароля.
