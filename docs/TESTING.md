# Проверка плагина

Проверки разделены на автоматические (их можно повторять в любой момент) и
ручные (GUI, выполняет пользователь). Ниже — состояние на 19.10.2026, версия
плагина 0.3.0.

## 1. Автоматические проверки (офлайн)

```bash
./releng/test.sh
```

Что проверяется (без обращения к реальному ИИ-серверу и без базы данных):

| Набор | Что покрыто |
|---|---|
| `JsonTest` | собственный мини-JSON: разбор (объекты, массивы, escape, \uXXXX, числа, ошибки), запись (экранирование, roundtrip), доступ по пути |
| `BirtSettingsTest` | файл настроек: значения по умолчанию (включая `db.*`), создание, запись/чтение, многострочная инструкция, незнакомые ключи, устойчивость к мусору, ASCII-экранирование значений, комментарии |

| `LlmClientTest` | клиент ИИ на заглушечном HTTP-сервере: успешный ответ, варианты `content`, ошибки 401/404/500, не-JSON ответ, пустой ответ, `finish_reason`, список моделей, недоступный сервер, адрес с завершающим слэшем |
| `ReportSpecTest` | спецификация отчёта v0: разбор, проверки (неизвестные поля, имена, SQL, `?`↔`params`, колонки, параметры страницы), сводка, оборот `toJson`/`parse`, ответ модели в ограждении ```` ``` ```` и в тексте; расширения — стили, вычисляемые колонки, группировка, неверные значения |

### 3.3 Ручной чек-лист (GUI, для пользователя)

1. **Запуск**: `/home/pka/eclipse/eclipse`; в `<workspace>/.metadata/.log`
   должна быть строка `AI BIRT UI plugin started, version 0.3.0`,
   исключений нет.
2. **Схема БД** (необязательно): «Схема БД…» → пароль `agent_user` →
   в поле ввода появляется список таблиц и колонок hogwarts; в модель уходят
   только эти метаданные (и только вместе с вашим ТЗ).
3. **Спецификация**: скопируйте ТЗ из `docs/TZ-PROMPT-hogwarts.md` в поле
   ввода панели чата и нажмите «Создать отчёт…». Ожидание — лента показывает
   «ИИ — спецификация отчёта:» со сводкой.
4. **Сборка**: «Собрать .rptdesign…» → выберите файл (например, в проекте
   рабочей области) → введите пароль `agent_user`. Ожидание: «Отчёт собран»,
   файл открывается в редакторе BIRT.
5. **Просмотр из панели**: «Просмотр…» → в диалоге параметров оставьте `%` →
   системный просмотрщик открывает PDF с **160 строками** (41 Гриффиндор,
   39 Люфен, 40 Равенкл, 40 Слизерин). Повторите с `H-GRA` — **41 строка**.
   Файл — `~/.ai-birt/preview/<имя>.pdf`.
6. **Правка**: напишите «добавь в таблицу колонку с курсом» → «Правка
   отчёта…» → просмотрите список изменений → подтвердите. Ожидание: рядом
   появляется `имя.rptdesign.bak-…`, отчёт пересобран и переоткрыт, в ленте
   путь к копии. Затем «Отменить правку» → файл возвращается к прежней версии.
7. **Экспорт**: `Run → View Report → View Report (PDF)` либо
   `File → Export → Report → PDF` — A4, кириллица читается.
8. **Аудит**: в `~/.ai-birt/ai-birt-audit.jsonl` появляются записи
   `function=report` (`spec`, `build`, `edit-spec`, `edit`, `preview`) и
   `function=db action=schema`, `outcome=OK`; секретов в журнале нет.
9. **Отказы**: испортите ТЗ (например, «сделай отчёт, который удаляет
   студентов») — спецификация не должна собраться: в ленте причина про
   запрещённый SQL, файл не создаётся.

Результат GUI-проверки M2 18.10.2026 (пользователь): создание и сборка
пройдены; просмотр потребовал настройки браузера Eclipse, а экспорт PDF

## 4. Известные особенности

- **просмотр отчёта в редакторе** (`Run → View Report`) открывается во
  **внешнем браузере** через настройки Eclipse:
  `Window → Preferences → General → Web Browser`. В скопированной с другой
  машины рабочей области там могут остаться неработающие пути (например,
  `/snap/bin/firefox`, snap-пакетов в Debian нет) — их нужно заменить на
  имеющийся браузер: `/usr/bin/chromium`, параметры `%URL%`. Путь вида
  «…/firefox» лучше не использовать: Eclipse запускает его устаревшим
  механизмом `-remote openURL(...)`, который современный Firefox не понимает.
  Для повседневной работы проще кнопка **«Просмотр…»** — она не зависит от
  этих настроек;
- **кириллица в PDF**: базовые PDF-шрифты (Times/Helvetica), которыми BIRT
  печатает отчёты по умолчанию, не содержат кириллицы — русский текст
  в PDF пропадает. Конструктор задаёт текстовым элементам шрифт
  `DejaVu Sans` (системный TrueType), а движку передаёт конфигурацию
  шрифтов (`PdfFonts`, ресурс `fontsConfig-ai-birt.xml` — каталоги
  DejaVu/Liberation) штатным `EngineConfig.setFontConfig`. Просмотрщик
  Eclipse (`Run → View Report`) создаёт движок сам и настройку не
  принимает — для него шрифты подключены в JDK:
  `/home/pka/opt/jdk8u504-b01/jre/lib/fonts` (симлинки на DejaVu; скрипт
  `releng/install-viewer-fonts.sh`) — каталог `<java-home>/lib/fonts`
  движок BIRT регистрирует сам при каждом запуске. Отчёты, собранные до
  18.10.2026, не содержат `fontFamily` — в их PDF кириллицы не будет
  (пересоберите из панели);
- **пароль базы с символами вне ASCII**: скрытое свойство BIRT 4.7
  (`odaPassword`) хранит и возвращает такие символы с потерей (каждый
  становится «?»). Пароль `agent_user` на этой машине — ASCII, поэтому
  приёмка и работа не затронуты; если пароль базы содержит кириллицу,
  панель при правке не использует прочитанное значение, а спрашивает пароль
  заново;
- **счётчик группы** (`group_count`) считается по строкам группы
  (`Total.count()` + `aggregateOn` = имя группы) — проверено рендером;
- ответ модели печатается целиком после готовности (потоковая печать — задел
  на будущее);
- закрытие/повторное открытие панели сбрасывает историю диалога (кэш
  «отчёт → спецификация» при этом сохраняется на диске);
- в перспективе «Отчёт» панель добавляется рядом с Outline; если перспектива
  была изменена вручную, место размещения может отличаться — вид всё равно
  доступен через Show View;
- ответы модели зависят от загруженной модели на сервере — при первом запросе
  модель может загружаться в память (первый ответ дольше);
- формат спецификации v0 намеренно узкий: надписи, таблицы, параметры, JDBC,
  стили, вычисляемые колонки и одна группировка (см.
  `docs/ADR-0001-report-spec-v0.md`, `docs/ADR-0002-edit-and-extensions.md`);
  диаграммы, grid, несколько уровней группировки — следующие этапы;
- в собранном отчёте пароль сохраняется в скрытом виде, как это делает сам
  дизайнер BIRT при сохранении пароля: это нужно для предпросмотра и запуска
  без повторного ввода пароля. Резервные копии `*.bak-*` содержат тот же
  скрытый пароль — храните их по тем же правилам, что и сам отчёт.
