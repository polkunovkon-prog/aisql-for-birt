# ADR-0002: правка отчёта, расширения спецификации v0, предпросмотр, схема БД и диаграммы

- **Статус:** принято (19.10.2026), реализовано в 0.3.0; расширено в 0.5.0–0.7.0
- **Контекст:** плагин «ИИ-конструктор отчётов» для BIRT 4.7;
  продолжение формата из ADR-0001

## 1. Правка собранного отчёта по замечанию

**Проблема.** После сборки отчёта пользователь почти всегда хочет доработать его
(«добавь колонку», «отсортируй по фамилии»), а не описывать заново. Модель не
умеет аккуратно «дописать патч» к файлу `.rptdesign` — единственный надёжный
источник правды — спецификация, из которой файл собран.

**Решение.** Правка идёт по паттерну «модель возвращает полную новую
спецификацию» (тот же, что в DBeaver-плагине):

1. панель помнит для собранного отчёта его спецификацию (в сессии — память;
   между сессиями — кэш `BuiltReports`, см. п. 4);
2. пользователь пишет замечание текстом; модель получает инструкцию
   (`SpecPrompts.editInstruction`) + текущую спецификацию + замечание;
3. модель возвращает **полную новую спецификацию**, клиент проверяет её так же
   строго, как при создании (ADR-0001);
4. клиент считает различия «было → стало» (`SpecDiff.describe`) и показывает
   список **до** применения — пользователь подтверждает;
5. применение: резервная копия `имя.rptdesign.bak-yyyyMMdd-HHmmss` → сборка
   **во временный файл** → атомарная замена (`Files.move`); при ошибке
   исходный файл не портится;
6. **«Отменить правку»** возвращает прежнюю версию из копии (пока приложение
   работает).

Правка запрещена, если файл отчёта был изменён вручную (в редакторе BIRT или
на диске): кэш сверяет время изменения и размер файла, при расхождении
спецификация считается устаревшей и операция предлагает пересобрать отчёт.

**Почему полная спецификация, а не «патч»:** патч требует второго языка
(«измени тело[2].колонки[1]»), модель в нём ошибается, а ошибки тихие; полную
спецификацию можно проверить теми же правилами, и за одну правку пользователь
видит всё, что изменится.

## 2. Расширения спецификации v0 (обратно совместимые)

Спецификация остаётся **v0**: старые файлы спецификаций валидны без изменений
(все новые поля необязательные, неизвестные поля по-прежнему запрещены).

| Где | Новое поле | Значение |
|---|---|---|
| `label` | `italic` | курсив надписи |
| `label` | `color` | цвет текста `#RRGGBB` |
| `table.columns[]` | `bold`, `italic`, `color`, `background` | стиль ячейки данных |
| `table.columns[]` | `header_background` | фон ячейки шапки |
| `table.columns[]` | `refs` | все `row["…"]` из `expr` (для привязок BIRT) |
| `table.columns[]` | `result_column` | привязка к колонке набора, когда `expr` — вычисление |
| `table` | `group_by` | колонка группировки (один уровень) |
| `table` | `group_title` | подпись заголовка группы (по умолчанию «Группа») |
| `table` | `group_count` | `true` — в подвале группы счётчик строк (`Total.count()`) |
| `table` | `total_label` | подпись строки итогов (по умолчанию «Итого») |
| `table.columns[]` | `total` | `sum`/`count`/`avg`/`min`/`max` — итог колонки в подвале таблицы |
| `table` | `groups` | до 5 уровней группировки: `expr`, `title`, `count` |
| `table` | `sort` | ключ или массив ключей `row["…"] asc\|desc` |
| `table` | `highlight` | подсветка строк: `when`, `color`, `background`, `bold`, `italic` |
| `table` | `filter` | строка-условие (JS-выражение), оператор `is-true` |
| `list` | — | список с `header`, `groups`, `sort`, `total_label` (0.7.0) |
| `grid` | — | сетка: строки/ячейки, объединения, вложенные элементы (0.5.0) |
| `image` | — | изображение: `path` (PNG-файл) или `base64`, `width_mm`/`height_mm` (0.5.0) |
| `report.page` | `header`, `footer` | колонтитулы с `{page}`, `{pages}`, `{title}`, `{date}` |
| `report.page` | `show_header_on_first`, `show_footer_on_last` | показ на первой/последней странице |
| `chart` | — | диаграмма: `kind`, `dataset`, `category`, `value`, `series`, `aggregate`, `title`, `width_mm`/`height_mm` (0.7.0) |

Стиль ячеек и надписей задаётся в спецификации **явно** (не через темы BIRT):
это переносимо и предсказуемо. Группировка таблицы и списка — до 5 уровней
(`groups`), форма одного уровня (`group_by`/`group_title`/`group_count`)
сохранена для обратной совместимости; `group_by` и `groups` взаимоисключающи.
Сортировка — один ключ или массив ключей с направлением (`sort`).

Вычисляемые колонки (`row["grade_level"] * 10`) работают через привязки
`boundDataColumns`: клиент создаёт вычисляемую колонку таблицы с выражением и
привязывает к её имени элемент данных. Записывать выражение прямо в
`resultSetColumn` нельзя: при сохранении модель BIRT «разрешает» такие
элементы по совпадению выражений с другими колонками и может перенаправить
ячейку (проверено на агрегате с тем же выражением — колонка начинала
показывать итог в каждой строке).

Итоги (`total`) устроены так же, как в дизайнере BIRT: вычисляемая колонка
таблицы с `aggregateFunction` (`sum`/`count`/`average`/`min`/`max`) и
аргументом-ссылкой на привязку колонки (`row["имя_привязки"]`); элемент данных
подвала привязывается к имени агрегатной колонки. Подпись (`total_label`)
ставится в первую свободную колонку слева. Это покрывает типовые отчёты
«список + Итого» (см. корпус `own.rar`).

## 3. Предпросмотр отчёта из панели

**Проблема.** Вкладка `Preview` дизайнера BIRT 4.7 отключена авторами
(Bugzilla 421879), а `Run → View Report` зависит от настроенного Web Browser
Eclipse — на практике это частая точка отказа.

**Решение.** Кнопка **«Просмотр…»**: панель сама выполняет отчёт штатным
`ReportEngine` (headless, PDF, с параметрами из диалога `ParamsDialog`) и
открывает готовый PDF системным просмотрщиком (`Program.launch`). Никакой
зависимости от Web Browser и вкладки Preview нет; шрифты PDF задаёт
`PdfFonts` (ADR-0001). HTML-предпросмотр не используется: PDF самодостаточен
и одинаково выглядит у всех.

## 4. Кэш «отчёт → спецификация» (`BuiltReports`)

Чтобы правка работала и **после перезапуска Eclipse**, соответствие «файл
отчёта → спецификация, из которой он собран» хранится в
`~/.ai-birt/reports-built.json`. Запись привязывается к файлу по пути,
времени изменения и размеру:

- файл не менялся → спецификация используется для правки/предпросмотра;
- файл изменился (правка в дизайнере, другой инструмент) → запись считается
  устаревшей и игнорируется — молча править «по старой спецификации» нельзя;
- кэш чистится от записей об исчезнувших файлах.

Кэш — дополнение к памяти сессии, а не замена: в рамках одной сессии
используется спецификация из памяти (она точнее).

## 5. Схема БД для модели — только метаданные; любая СУБД (0.3.0 → 0.7.0)

**Решение.** Кнопка **«Схема БД…»** читает у базы **только метаданные**
(`DatabaseMetaData`: имена таблиц, представлений и колонок с типами), без
единой строки данных, и вставляет текст в поле ввода — пользователь дополняет
его ТЗ. Ограничения: 60 таблиц, 40 колонок на таблицу (в текст добавляется
«… ещё N»), служебные схемы СУБД не показываются.

- текст схемы уходит в модель **только как часть ТЗ**, которую пользователь
  видит в поле ввода и может вырезать;
- строки данных не читаются вообще — это гарантия уровня кода
  (`DbSchema.read` вызывает только `getTables`/`getColumns`);
- подключение к базе задаётся в диалоге «Схема БД…» и (по желанию)
  сохраняется в `~/.ai-birt/ai-birt.properties` (`db.driver`, `db.url`,
  `db.user`, `db.password` — пароль только по галочке);
- для скриптов приёмки есть headless-инструмент
  `com.aisql.birt.core.jdbc.DbSchemaTool`;
- **любая СУБД** (0.7.0): `DbSchema.read(driver, url, user, password)` сначала
  идёт штатным путём BIRT (`JDBCDriverManager`), при неудаче — запасным
  `Class.forName` + `DriverManager`; PostgreSQL имеет быстрый путь. Драйвер
  должен быть установлен в Eclipse (комплектный — PostgreSQL 42.7.3).

Пароль базы в модель не попадает никогда (и из настроек, и из диалога он
уходит только в JDBC-соединение с базой).

## 6. Диаграммы (0.7.0)

**Решение.** Элемент спецификации `chart` собирается штатным **Chart API**
BIRT (`ChartWithAxesImpl`/`ChartWithoutAxesImpl`), а не XML-строкой:

1. `ChartFactory` строит модель: категории — базовая серия оси X, значения —
   `BarSeries`/`LineSeries` на оси Y с `SeriesGrouping` (`Sum`/`Average`/
   `Min`/`Max`/`Count`); для круговой — `PieSeries` во вложенном
   `SeriesDefinition` (эту структуру ожидает генератор запросов BIRT);
2. модель передаётся расширенному элементу `Chart` через
   `ChartReportItemImpl.setModel` (штатный путь конструктора; запасной —
   запись XML в `xmlRepresentation`);
3. в элементе задаются `dataSet` и `boundDataColumns` с `dataType`,
   взятым из колонок набора (без типа движок не приводит значения к числу);
4. размер блока диаграммы (`Block.Bounds`) задаётся в точках из
   `width_mm`/`height_mm`: при нулевых границах движок молча рисует в 0×0,
   и элемента в PDF/HTML просто нет (наступили на это на приёмке);
5. шрифт диаграммы — `DejaVu Sans`: иначе кириллица в PDF/SVG выходит
   «кракозябрами»;
6. легенда включается только при разбиении на ряды (`series`): без ряда у
   легенды нет подписи, и она рисовала бы маркеры без текста; для круговой
   легенда полезна всегда (подписи категорий).

**Ограничение среды.** Рендер диаграмм проверяется только в Eclipse OSGi:
standalone-движку не хватает OSGi-обработчика набора данных (падение в
`AbstractChartBaseQueryGenerator`). Сборка `.rptdesign` и тесты модели
работают и офлайн; приёмка диаграмм — `aibirtSelftest` под xvfb.

## Отклонённые варианты

- **Правка «диффом» от модели** (модель возвращает список изменений) —
  второй язык, тихие ошибки; см. п. 1.
- **Хранить спецификацию только в памяти сессии** — правка после перезапуска
  невозможна, а именно это нужно на практике.
- **Хранить спецификацию в самом `.rptdesign`** (свойство/комментарий) —
  изменение формата файла BIRT; при открытии в дизайнере и сохранении из него
  такие данные могут быть потеряны; кэш рядом с настройками прозрачнее.
- **Предпросмотр через встроенный браузер Eclipse** — зависит от настройки
  Web Browser; отклонено (см. п. 3).
- **Автоматический контекст схемы без ведома пользователя** — неявная
  передача имён таблиц в модель; в 0.3.0 текст схемы вставляет пользователь
  сам и видит его в поле ввода.

## Последствия

- правка отчёта — только для отчётов, собранных конструктором (или известных
  ему по кэшу); отчёты «из прошлой жизни» пересобираются из спецификации;
- файл отчёта остаётся штатным `.rptdesign`: резервные копии — обычные копии
  рядом с файлом, их можно удалять руками;
- расширения спецификации остаются необязательными: модель, не знающая про
  них, по-прежнему возвращает валидную v0-спецификацию;
- приёмка: `releng/m2-selftest.sh` прогоняет четыре спецификации (базовая,
  группы, условия+колонтитулы, сортировка+группы) и проверяет текст схемы БД
  (`DbSchemaTool`), не содержащий SQL и данных; диаграммы принимаются
  headless-приложением `aibirtSelftest` в Eclipse OSGi (PDF/HTML, SEVERE=0).
