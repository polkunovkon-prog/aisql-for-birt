## M1. Каркас + чат *(выполнен, 17.10.2026)*

- бандлы `com.aisql.birt.core` (настройки, JSON, клиент ИИ, аудит — чистая Java 8)
  и `com.aisql.birt.ui` (панель чата, страница настроек, стартовый маркер);
- установка штатными механизмами Eclipse (bundles.info; без патчей, без root)
  со сбросом кэшей и контрольным headless-запуском;
- сборка без Maven, офлайн-тесты, документация;
- подключена локальная модель; интерфейс на русском.

## M2. Спецификация и сборка отчёта *(выполнен полностью, 19.10.2026)*

Сделано (MVP «из чата рождается .rptdesign»):

- модель генерирует компактную **JSON-спецификацию** отчёта (страница,
  параметры, источник JDBC, набор данных, таблица) — не XML; формат
  зафиксирован в `docs/ADR-0001-report-spec-v0.md`;
- строгая проверка спецификации на клиенте (неизвестные поля, ссылочная
  целостность, `?`↔`params`, только читающий SQL) с понятными ошибками;
- сборка `.rptdesign` **штатным Design API BIRT** (мастер-страница, параметры,
  источник с паролем, набор, таблица, привязки, кэш метаданных);
- кнопки «Создать отчёт…» и «Собрать .rptdesign…» (диалог пути и пароля БД),
  собранный отчёт открывается в редакторе BIRT;
- комплектный драйвер PostgreSQL 42.7.3 через точку расширения `driverinfo`
  (PostgreSQL 17/SCRAM работает без замены файлов BIRT);
- шрифты PDF: текстовым элементам задаётся TrueType-шрифт с кириллицей
  (`DejaVu Sans`), конфигурация шрифтов передаётся движку штатным
  `EngineConfig.setFontConfig` — PDF со встроенными шрифтами;
- приёмка: `releng/m2-selftest.sh` (сборка + рендер PDF/HTML, проверка
  данных в HTML и кириллицы в PDF) и headless-приложение
  `com.aisql.birt.ui.aibirtSelftest` внутри Eclipse; готовый ТЗ-промт
  для базы hogwarts — `docs/TZ-PROMPT-hogwarts.md`.

Закрыто в 0.3.0 (19.10.2026):

- **правка собранного отчёта по замечанию** («Правка отчёта…»): полная новая
  спецификация от модели, список изменений до применения, резервная копия,
  атомарная замена, кнопка «Отменить правку»; кэш «отчёт → спецификация»
  (`~/.ai-birt/reports-built.json`) — правка работает и после перезапуска;
- **предпросмотр из панели** («Просмотр…»): headless PDF системным
  просмотрщиком, без вкладки Preview и Web Browser Eclipse;
- **расширения спецификации** (обратно совместимые): стили надписей и ячеек,
  вычисляемые колонки, группировка таблицы со счётчиком строк;
- решения и границы — `docs/ADR-0002-edit-and-extensions.md`.

## M3. Создание отчёта по описанию (ТЗ) с нуля *(начат, 19.10.2026)*

Сделано:

- контекст схемы БД для модели — **только метаданные** (имена таблиц и
  колонок, без строк данных): кнопка «Схема БД…» + `DbSchema`,
  `DbSchemaTool`; текст схемы вставляется в поле ввода, пользователь видит
  его в ТЗ (`docs/SECURITY.md`);
- перегенерация отчёта по замечанию («в шапке добавь дату») — через правку
  из M2 (полная спецификация + различия).

Осталось:

- работа с документацией/справочником BIRT как источником знаний для модели;
- полноценный цикл «ТЗ → отчёт» на сложных описаниях: несколько таблиц,
  диаграммы, grid, вычисляемые поля в шапке — расширение спецификации до v1
  по мере необходимости;
- автоматический (по кнопке) подбор схемы без ручного копирования текста —
  при сохранении правила «только метаданные, с ведома пользователя».

## Покрытие элементов BIRT — программа расширения

Архитектура **не ограничивает** набор элементов: сборка идёт штатным Design
API BIRT, поэтому можно создать всё, что создаёт сам дизайнер (таблицы,
grid, списки, кросс-таблицы, диаграммы, изображения, extended item, скрипты,
библиотеки). Ограничение — **словарь спецификации** и промт модели: он растёт
итерациями, каждая новая возможность закрывается тестами и приёмкой на
корпусе. Неизвестные поля по-прежнему запрещены: модель не может «написать
что угодно», пока формат это не описывает.

Измеренный корпус `own.rar` (655 отчётов; только этот корпус, без диаграмм
и кросс-таблиц):

| Элемент | Отчётов |
|---|---|
| таблица | 555 |
| grid | 466 |
| текст (rich text) | 536 |
| надписи | 643 |
| колонтитулы страницы | 113 (нижний) / 30 (верхний) |
| скрипты событий | 139 |
| extended item | 48 |
| изображения | 17 |
| list | 2 |
| диаграммы, кросс-таблицы | 0 |

Очередь расширений (по пользе для корпуса и типовых ТЗ):

1. ✅ **итоги таблицы** (`total`/`total_label`) — 0.4.0;
2. **колонтитулы страницы** (дата, номер страницы, название отчёта) — 113;
3. **grid** для бланков и сложной вёрстки (ячейки, объединения) — 466;
4. **изображения** (логотип, штрихкод) — 17;
5. **сортировка и многоуровневые группировки** — типовые ТЗ;
6. **list** (шаблон строки) — 2;
7. **диаграммы** (chart) — отдельный блок спецификации;
8. **кросс-таблица** (crosstab: куб, измерения, меры);
9. **extended item** — по именам классов, установленных у пользователя;
10. **скрипты событий** — только с предупреждением: скрипты BIRT исполняют
    Java-код, это риск; по умолчанию выключены.

Принципы расширения:

- обратная совместимость: новые поля необязательные, старые спецификации
  валидны;
- проверка не только схемы, но и результата: headless-открытие файла моделью
  BIRT и пробный рендер; при ошибке — понятное сообщение, для «экзотики»
  возможен ремонтный цикл «модель исправляет по тексту ошибки»;
- метрика покрытия: после каждого расширения — прогон анализатора по корпусу
  (сколько отчётов выражается спецификацией) и приёмка на реальных данных;
- corpus-driven: приоритет получают элементы, которые реально встречаются
  в отчётах пользователя, а не «все элементы ради всех».
