# Дорожная карта

Полный план работ — в документе
`~/Документы/ОТЧЁТ-возможность_ИИ-ассистента_в-BIRT_и-план-разработки.md`.
Здесь — краткая карта этапов и состояние.

## M1. Каркас + чат *(выполнен, 17.10.2026)*

- бандлы `com.aisql.birt.core` (настройки, JSON, клиент ИИ, аудит — чистая Java 8)
  и `com.aisql.birt.ui` (панель чата, страница настроек, стартовый маркер);
- установка штатными механизмами Eclipse (bundles.info; без патчей, без root)
  со сбросом кэшей и контрольным headless-запуском;
- сборка без Maven, офлайн-тесты (133 проверки), документация;
- подключена локальная модель; интерфейс на русском.

## M2. Спецификация и сборка отчёта *(MVP выполнен, 18.10.2026)*

Сделано (MVP «из чата рождается .rptdesign»):

- модель генерирует компактную **JSON-спецификацию** отчёта (страница,
  параметры, источник JDBC, набор данных, таблица) — не XML; формат
  зафиксирован в `docs/ADR-0001-report-spec-v0.md`;
- строгая проверка спецификации на клиенте (неизвестные поля, ссылочная
  целостность, `?`↔`params`, только читающий SQL) с понятными ошибками;
- сборка `.rptdesign` **штатным Design API BIRT**: панель чата получила
  кнопки «Создать отчёт…» и «Собрать .rptdesign…» (диалог пути и пароля БД),
  собранный отчёт открывается в редакторе BIRT;
- комплектный драйвер PostgreSQL 42.7.3 через точку расширения `driverinfo`
  (PostgreSQL 17/SCRAM работает без замены файлов BIRT);
- приёмка: `releng/m2-selftest.sh` (сборка + рендер PDF/HTML с проверкой
  данных) и headless-приложение `com.aisql.birt.ui.aibirtSelftest` внутри
  Eclipse; готовый ТЗ-промт для базы hogwarts — `docs/TZ-PROMPT-hogwarts.md`.

Осталось в M2 (следующая итерация):

- правка уже открытого в редакторе отчёта (применение/отмена изменений,
  журнал изменений), а не только создание нового файла;
- предпросмотр отчёта прямо из панели чата (без внешнего браузера и настройки
  Eclipse Web Browser);
- расширение спецификации: группировки, вычисляемые колонки, стили ячеек.

## M3. Создание отчёта по описанию (ТЗ) с нуля

- «сделай отчёт: …» → новый `.rptdesign` в проекте: полный цикл
  (источник данных → набор → параметры → разметка), затем M2-путь сборки;
- работа с документацией/справочником BIRT как источником знаний для модели;
- перегенерация отдельных частей по замечанию («в шапке добавь дату»).

## M4. Приёмка на наборе отчётов

- планка: набор `own.rar` (655 отчётов пользователя) — типовой отчёт
  «данные + параметры + таблица/сетка» плагин должен создавать самостоятельно;
- дополнительный набор совместимости: 16 форм из `~/ideaProj/ehr_template_v2`
  (BIRT 2.6.1…4.6) — должны открываться и корректно рендериться;
- прогон «ТЗ → отчёт» по документации, сбор замечаний, критерии готовности.
